FIXED
=========================================================================

1. [CRITICAL] The nightly bake was silently broken.

   compact-locations.js is a maintenance script, not data, but it matches the *-locations.js
   glob that all three bake steps use to find files. Every loader evaluates the file, and its
   `#!/usr/bin/env node` shebang is a SyntaxError. Reproduced:

       Loaded 0 override(s).
       SyntaxError: Invalid or unexpected token
         at loadLocationsFile (bake-overrides.js:53)

   bake.yml swallowed it with `|| echo "...continuing"`, so runs reported success. Net effect:
   every FlushPanel override baked into nothing. bake-confirmed wrote per-file inside its loop,
   so chains alphabetically before "compact-" baked and the rest never did.

   FIX: a looksLikeDataFile() content check in all three loaders — shebang or no
   `window.X = [` means skip, with the skip logged. Fixing the glob alone would leave the same
   trap for the next non-data file.

   Fixing that exposed a SECOND crash in bake-overrides.js: the chain-map loop iterated every
   globbed filename and dereferenced loaded[f].varName, which is undefined for a skipped file.
   Now iterates Object.keys(loaded).

   PROVEN END TO END, not just parsed. Against a sandbox copy of the real repo:
       Skipped non-data file(s): compact-locations.js
       Indexed 28123 locations across 41 file(s).
       albany-newkarner  ->  hrs, addr
       Done. 1 updated, 0 created, 0 removed, across 1 file(s).
   Before the fix, that run died on the first file and applied nothing.

1b. bake.yml hid the failure. All four `|| echo "...continuing"` lines now emit
    ::warning:: annotations, which surface on the run summary. Steps still continue.

1c. [FOUND WHILE VERIFYING 1 — this one is on me] Fixing the crash made a data-loss path live.

    bake-hours.js is authoritative: any record flagged community_verified whose id is ABSENT
    from the status file gets REVERTED to its pre-community hours. fetch-and-bake-hours.js
    wrote whatever Firestore returned with no check — so zero docs (transient error, permissions
    change, renamed collection) would silently wipe every community-verified hour. Confirmed by
    running it with an empty status file: 10 records reverted.

    fetch-and-bake.js already guarded this way ("Nothing to bake"); the hours fetcher didn't.
    FIX: refuse to bake an empty fetch, with an explanatory message.

    That guard protects 10 records today: speedway 8, circleK 1, stewarts 1.

2. Two true duplicates removed.
     circlek-tampa-ntelecommpkwy   0.0m from circlek-tampa-ntelecompkwy — "TELECOMM" vs
                                   "TELECOM" at the same address. Kept the correct spelling.
     node/11761691198              0.1m from node/2549926579 (100 1st Avenue) with no address
                                   of its own. Kept the one with the address.
   28,125 -> 28,123 records.

4. hasRestroom is now admin-correctable. The amenityOverrides rules allowed exactly ten keys and
   the new amenity wasn't one, so a wrong community vote on any of the 672 flagged rest areas or
   354 flagged Circle Ks could not be overridden from FlushPanel. Added to both the create and
   update allowlists with the same <=24-char string validation as its siblings.

6. 85 dead CSS declarations removed from styles.css.
   styles.css and shell.css shared 35 selectors with 117 conflicting declarations; shell.css
   loads second and won every one, often via !important. Those declarations shipped to every
   user and did nothing — and worse, editing them silently had no effect.
   Removed only where shell.css sets the SAME property for EVERY selector in the rule.
   31 conflicts remain and are correct: they live in multi-selector rules where the other
   selectors still need the declaration. Zero single-selector conflicts left.
   Includes the stale `--accent: #38b8bb`, which never applied — #2ea1aa is the live value.

8. firestore.rules no longer claims a Cloud Function that doesn't exist. The comment on
   /leaderboard and /userStats said they are "written ONLY by the leaderboard Cloud Function";
   only recomputeBathroomAggregate and recomputeHourStatus are deployed. Reworded to state that
   no writer exists and the rules stay closed so any future writer must be server-side.

11. Accessibility and consistency on close buttons.
    aria-label added to installClose, listViewClose, accountClose — the other three already had
    one. cbClose used U+00D7 (×) while the other five used U+2715 (✕); normalised.

13. flushpanel.html "Handicap accessible" -> "Wheelchair accessible", matching the product
    direction. Admin-only string.

BONUS (not in the original 13, found during re-verification)
    jacksons-way-615371860 had sat:"" and sun:"" in its per-day hours map. An empty string is
    neither open nor closed — the app has a real 'closed' token — so it was a conversion
    artifact that would render as an unparseable window. Removed those two keys, so those days
    now read as UNKNOWN, which is what is actually known. This was the last malformed per-day
    value in the dataset.

NOT FIXED — deliberately
=========================================================================

3. Two stores share one set of coordinates. NOT duplicates — two real, different street
   addresses at identical lat/lng, meaning one pin of each pair is in the wrong place:

     Circle K, Franklin TN       1501 MURFREESBORO RD  /  1501 NEW HWY 96 W
     Cumberland Farms, Bridgewater MA   1001 Pleasant St  /  33 Main St

   Plus one ambiguous case (Circle K Jacksonville 3631 BLANDING BLVD vs "BLDG 2") which may
   genuinely be two units in one plaza.

   Fixing these needs an authoritative coordinate for the misplaced store. That cannot be
   derived from the data on hand — it needs the chain's store locator or Street View. A
   confident wrong coordinate is worse than a flagged one, so all of them are left in place and
   documented in coordinate-review.txt, with instructions for entering the fix as a FlushPanel
   override (lat/lng are both in the bake FIELD_MAP, and the bake now works).

5. amenityOverrides has no writer. app.js reads it in three places; FlushPanel has zero
   references. The whole admin-authoritative amenity path is a read with nothing writing it.
   This is a missing feature, not a defect — building the FlushPanel UI for it is a product
   decision, not a fix.

7. Four features have working JS and no HTML: loadLeaderboard(), updateMyProgressBadge(), the
   support-prompt overlay, and the recap pills. All are null-guarded, so nothing crashes; they
   simply return immediately. Deleting working code for a planned feature (Community/leaderboard)
   would mean rebuilding it later, so instead the status is now documented in a comment at
   loadLeaderboard so the next reader knows it is intentional rather than broken.

10. WITHDRAWN — this was a false positive in my own report. I said "Where Am I?" was the only
    primary control with no icon; it has an inline SVG crosshair plus an aria-label, and my check
    only looked for emoji. The real observation is milder: three controls use emoji (🚽 📋 📍)
    and one uses inline SVG. The SVG is arguably the better implementation — crisp, themeable, no
    cross-platform emoji variance — so it is left alone. Making all four consistent is a design
    choice in either direction and yours to make, not something to change silently.
