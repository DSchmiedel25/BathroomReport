═══ MUST-FIX 1 — H-01, public vote reads exposed location histories ═══
`votes` was `allow read: if true`, and every document carries:

    clientId (the raw uid) · locId · ratedAt · username

So anyone could query the collection and reconstruct WHERE A NAMED PERSON HAD BEEN AND WHEN. No
sign-in required. Phase 2a closed users/{uid} for precisely this reason and left the collection it
mirrors — I shut the front door and left the side one open.

It also sits three lines from the FAQ claim that analytics "doesn't identify you personally".

  Now: allow read: if signedIn() && (resource.data.clientId == request.auth.uid || isAdmin())

WHAT THAT BROKE, AND HOW IT IS HANDLED
  The weekly recap verified every activity entry by reading the vote behind it — which required
  permission to read OTHER people's votes. Closing the collection would have silently reduced the
  recap to counting only your own activity.

  The cleanup moved to where it belongs. recomputeBathroomAggregate now deletes an activity entry
  when its vote is deleted, so the log stays honest without every client being able to audit it.
  Best-effort and non-fatal: a stale entry is cosmetic, failing an aggregate write over one is not.

EVERY REMAINING votes READ, CHECKED AGAINST THE NEW RULE
  own vote by id                    PASSES  clientId is the caller
  query where clientId == my uid    PASSES  provably owner-scoped, the documented list pattern
  cross-user read in the recap      REMOVED replaced by the server-side cleanup
  the anon-migration query          DENIED  and that is correct. It filters by a DEVICE id, so it
                                            is not owner-scoped. Anonymous votes cannot exist
                                            anyway — the create rule requires signedIn() and pins
                                            the doc id to request.auth.uid. Now logged as
                                            "expected" rather than as a failure on every signup.

WHAT IS STILL PUBLICLY READABLE, DELIBERATELY
  aggregates    anonymous totals, no author attached
  activity      carries a chosen handle, not a uid, and public credit is the point of the feature
                you asked for. Weaker than the votes exposure and consented by design.
  outOfOrder    carries reporterId, but the app must read it for any location while signed out.
                Smaller surface: only people who report outages. Worth revisiting.
