WHAT IT CHECKS, AND WHICH BUG EACH ONE CAME FROM

  1. SIBLING GEOMETRY — all four drawer row types must be flex, gap 10px, same left padding.
     Came from: Gift shop is an <a>, so `.d-items button` never reached it. 16px vs 20px.

  2. ICON SLOT CONTEXT — no emoji may sit outside a .d-ico span.
     Came from: every icon was inline text, and emoji advance widths differ, so each label
     started at a different x.

  3. STALE SELECTORS — no drawer id may carry position:absolute or justify-content:center.
     Came from: #passportToggle left in the old floating map-control stack. Invisible to a
     conflict check because nothing competed with it.

  4. DUPLICATED CONSTANTS — CONFIRM_THRESHOLD vs MIN_YES, and more than one date string.
     Came from: three hand-typed dates that had drifted to July 14 / 21 / 30, and the earlier
     MIN_YES=2 vs CONFIRM_THRESHOLD=3 mismatch.

Check 3 found a bug I had missed even while writing the fix: #openNowToggle moved into the
drawer as "Hide confirmed closed" but kept position:absolute and justify-content:center. It
LOOKS fine today only because margin-left:auto on the switch masks it — one rule change from
mattering, and the identical rule that centred Passport. Removed, along with its dead
#openNowToggle.active green-pill rule (the JS uses .on now, verified).


========================================================================
DRAWER ALIGNMENT — four causes
========================================================================

A. Passport was CENTRED. styles.css still listed #passportToggle in the old map-control stack
   (position:absolute, justify-content:center). shell.css overrides display, width and
   text-align for drawer buttons but never justify-content.
   My v2.6.3 dead-CSS pass could NOT have caught it — that pass only removed declarations where
   shell.css sets the same property, and nothing competed with this one.

B. Gift shop sat 4px left. An <a class="d-shop-link">, so the button rule never applied:
   padding 14px 16px vs 20px, weight 600 vs 700, display:block vs flex.

C. Every label started at a different x, because icons were inline text. Fixed with a
   fixed-width column: #appDrawer .d-ico{ flex:0 0 1.6em; display:inline-flex; justify-content:center; }
   Ten static rows plus the four group toggles. CK_GROUPS had the emoji baked into the label
   string, so it was split into { icon, label }; both renderers updated, labels now escaped.

D. [from your second screenshot] "Getting around" and "Directions app" still butted against
   their icons. They are .d-section-label divs, not buttons — never given display:flex or gap,
   so .d-ico had no flex context: flex-basis ignored, gap inert. Now flex with gap 10px like
   every other row.


========================================================================
THE DATE PROBLEM — fixed at the root
========================================================================

Three hand-typed dates, already drifted: drawer stamp 2026-07-30, onboarding July 14, FAQ
July 21. Now one value:

    const BUILD_DATE = '2026-07-30';      // app.js, beside CONFIRM_THRESHOLD

buildDateLong() formats it for prose; stampBuildDate() fills .onboardingUpdated, .hiw-updated
and the drawer stamp (which carries data-version="v2.6.5" so version and date compose from one
place). ON EACH RELEASE change BUILD_DATE and data-version; nothing else shows a date. The
markup keeps July 30 as a no-JS fallback. Parsed as parts, not new Date(), so it can't shift a
day backwards west of GMT — tested at 2026-01-01, 2026-07-30, 2026-12-25.
