THE CHANGE
  "Is there a public restroom here?" was scoped to records flagged osm.restroomUnconfirmed.
  amenitySettled() already stops the question once an admin sets it or the community confirms
  it — but it knows nothing about the SOURCE data, so a place whose own operator data says
  "yes" could still have been asked.

  restroomDoubted() now also returns false when:
     loc.osm.restroomConfirmed      the operator's own locator says yes
     loc.meta.toilets === 'yes'     an OSM survey says yes

  Today this changes nothing: 1,032 records are flagged and NONE of them carries a positive
  claim, so the behaviour was already correct. It was correct by accident though — a property
  of the current imports, not a rule — and the next import could set both on one record. This
  makes it a rule, and check 11 fails the build if the data ever reaches that state.

WHAT I VERIFIED
