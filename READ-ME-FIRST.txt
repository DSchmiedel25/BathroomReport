THE CHANGE
  When hour status dropped from verified to pending or conflict, the document kept the previously
  verified value, kind, confirmedAt AND source:'community_verified'. A conflicted record was
  indistinguishable from a live verified one to anything that did not check the `verified` flag.

  bake-hours.js DOES check it (line 29), so no wrong hours were ever baked — the impact was
  smaller than the audit implied. But FlushPanel's conflict rows rendered that stale value as
  though it were the value in dispute, so an admin reviewing conflicts saw hours that were not
  actually in conflict.

  Now, when a doc is not verified:
     value, kind, confirmedAt, lastConfirmedAt   -> null
     source                                      -> null, not 'community_verified'
     prevValue, prevKind, prevConfirmedAt        -> the history, clearly named
  schemaVersion bumped 1 -> 2.

  FlushPanel shows "was 0500-2300" for a conflict, plus the date it was last confirmed.
